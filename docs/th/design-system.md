# ระบบดีไซน์ QPOS ร้านหม่าล่า

## เป้าหมาย

ทำให้ระบบดูเป็นมืออาชีพ ใช้งานง่ายสำหรับร้านหม่าล่าและเครื่องดื่ม แต่ยังเป็น dashboard/POS ที่อ่านข้อมูลเร็ว เหมาะกับการใช้งานซ้ำทั้งวันของเจ้าของร้าน แอดมิน และแคชเชียร์

## แนวคิดจากคอนเซปต์

- หน้าจอหลักเป็นระบบปฏิบัติงาน ไม่ใช่ landing page
- Sidebar อยู่ซ้าย ใช้พื้นหลังเข้มและตัวอักษรชัด
- พื้นที่ทำงานหลักใช้พื้นขาว/เทาอ่อน อ่านง่าย
- สีหลักเป็นแดงหม่าล่าแบบสุภาพ ใช้กับเมนู active, ปุ่มหลัก, และยอดสำคัญ
- ข้อมูลขายและสต็อกควร scan ได้เร็วผ่าน card, chart, table และ alert
- หน้า POS ต้องเน้นความเร็ว: ค้นหา, เลือกสินค้า, ดูบิล, รับเงิน, ชำระเงิน ในหน้าเดียว

## Typography

- ใช้ font stack: `system-ui, "Noto Sans Thai", "Segoe UI", sans-serif`
- หัวข้อหน้า: น้ำหนัก 700, อ่านง่าย, ไม่ใหญ่เกิน dashboard
- เมนูและปุ่ม: น้ำหนัก 600, ขนาดกะทัดรัด
- ตาราง: เน้นความอ่านง่าย ใช้หัวตารางสี muted และไม่บีบตัวอักษร
- Letter spacing ต้องเป็น `0` เพื่อไม่ทำให้ภาษาไทยอ่านยาก

## Layout

### App Shell

- Sidebar กว้างพอให้เมนูไทยไม่ตัดคำ
- Top bar กะทัดรัด มีชื่อสาขา/ผู้ใช้/สถานะ
- Content ใช้ spacing สม่ำเสมอ ไม่ใส่ card ซ้อน card เกินจำเป็น
- Card radius ไม่เกิน 8px

### Dashboard

- แถวบน: summary card สำหรับยอดขาย, บิลวันนี้, ลูกค้า, สินค้าใกล้หมด
- กลางหน้า: chart ยอดขายและช่องทางชำระเงิน
- ล่างหน้า: รายการบิลล่าสุดและสินค้าใกล้หมด
- หลีกเลี่ยงสีฉูดฉาดหลายสีพร้อมกัน

### POS

- ซ้าย/กลาง: search, category filter, product grid
- ขวา: บิลปัจจุบัน, ส่วนลด, รับเงิน, เงินทอน/ค้างชำระ, ปุ่มชำระเงิน
- Product card ต้องมีรูปสินค้า ชื่อ ราคา และหน่วยนับ
- Cart row ต้องมีจำนวน ปุ่มเพิ่ม/ลด ลบ และยอดรวม
- ปุ่ม `ชำระเงิน` ต้องเป็น visual priority สูงสุด

## Component Rules

- ปุ่มหลักใช้ `--qpos-primary`
- ปุ่มลบ/ล้างบิลใช้ `--qpos-danger`
- สถานะสำเร็จหรือเงินทอนใช้ `--qpos-success`
- Form input ต้องสูงพอสำหรับ touch และอ่านภาษาไทยได้ชัด
- Empty state ต้องเป็นภาษาไทยและบอก next action สั้น ๆ
- Icon ใช้เฉพาะช่วยสแกนเมนูหรือ action ไม่ใช้เป็นของตกแต่งเกินจำเป็น

## Copy Rules

ใช้คำไทยที่สั้นและตรงงาน:

- `Dashboard` -> `แดชบอร์ด`
- `POS` -> `ขายหน้าร้าน`
- `Product` -> `สินค้า`
- `Category` -> `หมวดสินค้า`
- `Customer` -> `ลูกค้า`
- `Supplier` -> `ผู้จำหน่าย`
- `Purchase` -> `ซื้อสินค้า`
- `Sale` -> `ขายสินค้า`
- `Report` -> `รายงาน`
- `Settings` -> `ตั้งค่า`
- `Checkout` -> `ชำระเงิน`
- `Clear Cart` -> `ล้างบิล`
- `Search Product` -> `ค้นหาสินค้า`

## Placeholder Rules

- Product name: `เช่น หมูสามชั้นหม่าล่า`
- Category name: `เช่น หม่าล่าเสียบไม้`
- Unit name: `เช่น ไม้, แก้ว, ชุด`
- Customer name: `เช่น ลูกค้าหน้าร้าน`
- Supplier name: `เช่น ร้านวัตถุดิบสด`
- Search text: `ค้นหาสินค้า ชื่อลูกค้า หรือเลขที่บิล`

## Responsive Rules

- Desktop: sidebar + content + POS cart ต้องเห็นครบโดยไม่ซ้อนกัน
- Tablet: POS product grid ลดจำนวน column ได้ แต่ cart ยังต้องใช้งานได้
- Mobile: ยอมให้เลื่อนแนวตั้ง แต่ปุ่มชำระเงินต้องหาเจอง่าย
- ห้ามให้ปุ่มหลักหรือข้อความยาวล้นกรอบ

## Intentional Deviation From Image Concept

ภาพ concept ใช้เพื่อกำหนดทิศทาง layout, density, palette และ workflow เท่านั้น ข้อความในภาพบางส่วนอาจสะกดไม่ตรงหรือไม่ใช่คำไทยที่ดีที่สุด การ implement ให้ยึด copy rules ในเอกสารนี้เป็น source of truth
